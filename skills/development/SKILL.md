# 开发期约束

- 对必须在开发阶段解决的问题，不要添加运行时容错、静默降级、假成功或吞异常后继续成功流程的逻辑。
- 对资源路径错误、资源类型错误、场景加载失败、重复调用或非法调用等显式配置或调用问题，明确暴露失败，使其能在开发阶段被发现并修正。
- 根据调用场景抛出异常，或使用明确的 Error 日志、失败状态或失败回调；确保调用方和调试者能确认流程已经失败，不得让框架将其视为正常流程。
- 可以在暴露错误前清理内部状态、释放半初始化 handle 或复位运行标记；清理仅用于避免污染调试现场，不得掩盖错误或让错误流程继续运行。
- Git commit message 使用中文。
